# Architecture Decision Records

ADRs capture decisions whose consequences span multiple modules or are costly
to reverse.

## Format

Each ADR contains:

- Status
- Date
- Context
- Decision
- Consequences
- Alternatives considered, where useful

Statuses normally are `Proposed`, `Accepted`, `Superseded` or `Rejected`.

ADRs describe decisions, not project history. When a decision changes, add a
new ADR and mark the old one superseded rather than rewriting the old decision
out of existence.

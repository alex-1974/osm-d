# osm-d v0.1.0

v0.1.0 is the first deliberately qualified standalone release of osm-d.

## Highlights

- high-performance validated PBF reading with borrowed semantic views;
- bounded block-parallel PBF validation/summary decoding;
- loss-aware durable PBF document model and semantic PBF writer;
- streaming OSM XML and osmChange read/write support;
- deterministic OSM API-style upload validation;
- compact editable `OsmStore` with stable handles, primary lookup and parent
  indexes;
- direct transactional PBF-to-store construction without a mandatory
  `PbfDocument`/`OwnedDataset` intermediate.

## Compatibility

The release is intentionally **v0.1.0**, not 1.0. The v0.1.x line has a
documented source-compatibility promise while preserving room for deliberate
v0.2 API evolution after independent consumer experience.

Release floor: D frontend 2.111 and DUB 1.40.0.

Qualified compiler matrix:

- DMD 2.111.0, 2.112.1, 2.113.0;
- LDC 1.41.0, 1.42.0, 1.43.0.

The first release gate is Ubuntu 24.04 x86_64.

See `docs/API_STABILITY.md` for the exact supported import/API/lifetime
boundary.

## Evidence

The pinned Geofabrik 2026-09-01 Monaco, Liechtenstein, Bremen and Austria
corpus is checksum-pinned in the repository. Complete semantic decode counts
match libosmium 2.23.0 on all four datasets.

Representative release evidence includes:

- Bremen serial `PbfReader`: 700.879 ms p50;
- Bremen four-worker parallel summary: 330.516 ms p50, 2.12x vs serial;
- warmed reusable Bremen reader workspace: 0 D-GC bytes and 0 collections on
  second and third complete reads;
- direct Bremen PBF -> indexed store: 2,268.417 ms;
- direct-store final RSS: 349.520 MiB; peak/final 1.070398x;
- Monaco semantic PBF write: 136.201 ms p50;
- Monaco OSM XML write: 273.119 ms p50;
- Monaco materializing OSM XML read: 1,113.736 ms p50.

Exact contexts, corpus hashes and interpretation are in
`docs/RELEASE_BASELINE.md`.

## Install

```sdl
dependency "osm-d" version="~>0.1.0"
```

See `docs/GETTING_STARTED.md` and the standalone packages under `examples/`.

## Known boundaries

v0.1.0 does not promise ABI stability, a persistent store file format,
concurrent store mutation, rendering/spatial indexing, filesystem/network
policy, or compatibility of low-level wire/codec implementation modules.

Literal JOSM-export provenance remains tracked as evidence hardening in #85 and
is not a semantic/API blocker for this release.

# osm-d v0.2.1

v0.2.1 is a focused correctness hotfix for the v0.2 editable-store upload
reconciliation contract.

## Fixed

OSM API diffResult entries cannot always be interpreted from field shape alone.
In particular, `delete if-unused` may succeed without deleting an object and
return its current `new_id` and `new_version`. The same raw field shape is
used by ordinary modify.

v0.2.1 adds request-context-aware `UploadResultEntry.effectFor` and updates
`OsmStore.applyUploadResult` to use the exact uploaded change entry:

- confirmed deletes still invalidate the deleted handle;
- retained conditional deletes restore the authoritative pre-edit baseline and
  keep the handle valid;
- already-deleted conditional results finalize the local tombstone;
- malformed/mismatched results still fail before acknowledgement mutation.

The existing `UploadResultEntry.action` property remains available for
v0.2.x source compatibility but is documented as a context-free legacy shape
guess.

The raw model also accepts bare delete acknowledgements using a negative
placeholder ID and no longer documents type+oldId as globally unique in a
general diffResult.

## Upstream evidence

The hotfix is based on current OpenStreetMap Rails behavior:

- `lib/diff_reader.rb` returns new ID/version when conditional delete catches
  already-deleted or precondition-failed state;
- the server test `test_upload_delete_if_unused` requires that response for
  retained Node, Way and Relation objects;
- server tests also exercise placeholder reuse where multiple result entries
  share the same old placeholder ID.

## Compatibility

This is an additive/corrective v0.2.x patch. No supported v0.2 public symbol is
removed or renamed. The compiler floor and release matrix remain unchanged.

## Install

```sdl
dependency "osm-d" version="~>0.2.0"
```

Consumers already using `~>0.2.0` may upgrade without source changes.
